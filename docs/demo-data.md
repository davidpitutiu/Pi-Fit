# Test history for progress and exports

The included `firebase/demo-workouts.v1.json` is an AppStore v1 export containing
**36 synthetic workouts, 572 completed sets and 16 exercise IDs**. Workouts are
labelled `TEST DATA` in both their names and notes. They cover 24 July–14 October
2026 in Europe/Bucharest, with load progression, RPE and realistic durations.
The 7/28/90-day demo counts as of 15 October are 3 / 12 / 36 workouts. The file
contains no real user identity, weight, height, Health records or credentials.
A [sample report](sample-test-history.pdf) was generated by Pi Fit from this data.

## Import into the Firebase account

This is an administrative operation against **pi-fit-663f2**. The supplied public
Firebase client config and an Auth UID are not administrative credentials.
The helper uses official Application Default Credentials and verifies that the
specified Auth user exists before reading or writing its backup.

On Windows install Node.js 22 and the [Google Cloud CLI](https://cloud.google.com/sdk/docs/install).
Open PowerShell at the Pi-Fit repository root. If the phone already has data to
keep, use **Profile → Save cloud backup** first so that data is included in the
server-side merge. Seeding cannot see unsaved, device-only data.

```powershell
git pull origin main
npm.cmd --prefix firebase/functions ci
gcloud auth application-default login --project pi-fit-663f2
node firebase/functions/scripts/seed_demo.cjs --uid "YOUR_AUTH_UID" --dry-run
```

Sign in through Google's browser flow with a project owner or an identity with
the required Firebase Auth read / Firestore read-write permissions. No password,
access token or service-account private key needs to be shared in chat or added
to the repository. Normal ADC login does not require setting
`GOOGLE_APPLICATION_CREDENTIALS` to a downloaded client SDK file.

The default dry-run refuses an account with no cloud backup. For a new account
with no existing server backup, explicitly add `--create-if-missing`:

```powershell
node firebase/functions/scripts/seed_demo.cjs --uid "YOUR_AUTH_UID" --dry-run --create-if-missing
```

Inspect the counts, then run the same command with `--apply` instead of
`--dry-run`. Keep `--create-if-missing` only when applicable:

```powershell
node firebase/functions/scripts/seed_demo.cjs --uid "YOUR_AUTH_UID" --apply --create-if-missing
```

The helper appends missing workout IDs only. It preserves existing same-ID
records (including edited demo workouts), profile values, active workout,
measurements, routines, calendar, favorites and other existing fields. A repeat
import adds no duplicates. It rejects invalid/unsupported backups and documents
at or above a conservative 700,000-byte JSON limit.

For an existing backup, the helper archives its exact previous document under
`users/<uid>/backups/before_demo_<random-id>` in the same Firestore transaction as
the merge into `users/<uid>/backups/current`. The archive path is printed. The
installed app manages only `backups/current`; these administrator-created
archives require separate cleanup in Firestore if all account cloud data is to
be removed. No archive is created for a no-op or a new empty account.

## Load the cloud data on the phone

Sign into the same account in Pi Fit and choose **Profile → Restore from cloud**.
The application deliberately does not automatically replace local data when a
server document changes. The restore dialog explains local replacement and the
app retains its existing local recovery copy.

Open **Progress** to inspect periods, streaks, exercise records and muscle focus.
Use **Export progress** for a PDF over custom dates or all time. Demo data counts
in these statistics, so do not treat it as real training or health history.

If the default Firestore database does not exist, create `(default)` in the
Firebase Console. If the phone reports `PERMISSION_DENIED`, publish the included
owner-only rules from an authenticated Firebase CLI shell; Admin access does not
prove that the signed-in mobile client can read the backup:

```powershell
firebase.cmd login
firebase.cmd deploy --only firestore:rules --project pi-fit-663f2
```

The current cloud agent has no usable Google administrative credentials: its
SDK check returned `app/invalid-credential` before reading the requested user.
No Firebase account or document was changed during preparation. Local tests and
fixtures do not establish that a real cloud import has succeeded.

## Generate a fresh fixture

The default fixture has fixed dates for repeatability. To generate a new dated
file with Python 3.9+ and the Europe/Bucharest timezone database available:

```sh
python3 scripts/generate_demo_data.py --as-of YYYY-MM-DD --output /path/demo.json
node firebase/functions/scripts/seed_demo.cjs --uid YOUR_AUTH_UID --datafile /path/demo.json --dry-run
```

The cutoff is exclusive Bucharest midnight; future cutoff dates are rejected.
The standalone generator can merge a plain export using `--base`, preserving
existing rows. Its optional body-measurement flag is intended for a separate
explicit local fixture; the Firebase helper imports workout history only and
never copies personal profile/measurement data from a fixture.
